🔧 主要工作内容

问题修复 RTX 5090 GPU 架构兼容性修复

问题：RTX 5090 采用 Blackwell 架构 (sm_120)，而容器中的 PyTorch 2.5 (来自 nvcr.io/nvidia/pytorch:24.10-py3) 最高只支持到 sm_90，导致 CUDA kernel 无法执行。

解决方案：在 Dockerfile 中强制升级 PyTorch 到支持 cu126 的版本

python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu126 --force-reinstall

问题修复 Text Encoder 服务启动失败

问题：healthcheck 在模型加载完成前就超时，容器状态为 Created 但未启动

根因：GPU 显存占用过高 (GPU 0: 16969MiB/100%)，模型加载缓慢

解决方案：调整 docker-compose.yaml 中的 GPU 配置和模型挂载路径

功能增强 ModelScope 模型集成

改动：在 docker-compose.yaml 中添加 ModelScope 模型挂载

volumes: - ${HOME}/.cache/modelscope/hub/models/LLM-Research/Meta-Llama-3-8B-Instruct:/workspace/llama-3-8b-instruct:ro

目的：支持使用国内 ModelScope 镜像源下载和加载 LLM 模型

💡 技术要点总结

1. RTX 5090 架构特性

RTX 5090 采用 Blackwell 架构 (compute capability 12.0)，需要 PyTorch 2.6+ 或 cu126 版本才能支持。 旧版本 PyTorch 最高只支持到 sm_90 (Hopper 架构)。

2. Kimodo 文本编码器架构

项目使用 LLM2Vec 包装器将 LLM 转换为文本编码器，基于 Meta-Llama-3-8B-Instruct 模型。 文本编码器作为独立服务运行在 9550 端口，通过 API 提供给主 demo 服务调用。

3. 运动数据转换流程

项目支持多种运动数据格式 (BVH, SMPL, SMPL-X)，通过 CLI 工具和转换库实现格式间的互操作。 动捕数据可以转换为 BVH 后，提取关键帧作为全身约束输入到生成模型。
