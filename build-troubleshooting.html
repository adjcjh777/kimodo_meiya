问题 #1

PyTorch 不支持 RTX 5090 (sm_120 Blackwell)

现象

text-encoder 容器启动后 Python 进程在跑但 Gradio 服务无法启动，healthcheck 一直 unhealthy。查看日志发现：

NVIDIA GeForce RTX 5090 with CUDA capability sm_120 is not compatible
with the current PyTorch installation.
The current PyTorch install supports CUDA capabilities
sm_70 sm_72 sm_75 sm_80 sm_86 sm_87 sm_90 compute_90.
根本原因

Kimodo 的 Docker 基础镜像 nvcr.io/nvidia/pytorch:24.10-py3 自带 PyTorch 2.5.0，该版本编译时最高支持到 sm_90（Hopper）。RTX 5090 是 Blackwell 架构，计算能力为 sm_120，不在支持列表中。PyTorch 初始化 CUDA 失败，导致模型无法加载到 GPU。

修改措施

在 Dockerfile 的 pip install 步骤中强制升级 PyTorch 到支持 sm_120 的版本：

RUN --mount=type=cache,target=/root/.cache/pip \
    python -m pip install --upgrade pip \
 && python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128 --force-reinstall --timeout 300 --retries 5 \
 && SKIP_MOTION_CORRECTION_IN_SETUP=1 python -m pip install -r docker_requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple --timeout 120
关键认知
  • RTX 5090 (Blackwell) 的计算能力是 sm_120，非常新
  • PyTorch 需要在编译时就支持对应的 compute capability，不能事后添加
  • PyTorch 官方从 cu128 版本开始支持 Blackwell 架构
问题 #2

cu130 版本要求 CUDA Driver 13.0+，主机只有 12.9

现象

将 Dockerfile 改为 cu130 后构建成功，但容器启动时 CUDA 初始化失败：

CUDA initialization: The NVIDIA driver on your system is too old
(found version 12090). Please update your GPU driver by downloading
and installing a new version from the URL: http://www.nvidia.com/Download/index.aspx
Alternatively, go to: https://pytorch.org to install a PyTorch version that has
been compiled with your version of the CUDA driver.

torch.cuda.is_available() 返回 False，GPU 不可用。

根本原因

PyTorch cu130 需要主机 NVIDIA 驱动版本 ≥ 570+ (CUDA 13.0)。当前主机驱动版本为 575.64.03（对应 CUDA 12.9），不满足要求。

这里有一个容易混淆的概念：

  • CUDA Toolkit（容器内）：PyTorch 自带的 CUDA 库，如 cu128、cu130
  • CUDA Driver（主机）：NVIDIA 驱动提供的 libcuda.so，有最低版本要求
  • PyTorch 的 CUDA Toolkit 版本可以高于主机 Driver 版本，但 Driver 必须满足最低要求
约束关系：
cu128 → 需要 CUDA Driver ≥ 12.8 ✅（主机 12.9 满足）
cu130 → 需要 CUDA Driver ≥ 13.0 ❌（主机只有 12.9）
修改措施

将 Dockerfile 中的 CUDA 版本从 cu130 改为 cu128：

# 改之前
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu130

# 改之后
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128

cu128 的 PyTorch (2.11.0) 同时满足两个条件：支持 sm_120 + 只需要 Driver 12.8+。

问题 #3

清华 PyTorch 镜像源 404 — 不支持 cu128

现象

为了加速下载，将 PyTorch 源改为清华镜像后，pip 直接报错：

ERROR: Could not find a version that satisfies the requirement torch (from versions: none)
ERROR: No matching distribution found for torch

构建在第 11 步就失败了，连下载都没开始。

根本原因

清华大学的 PyTorch wheel 镜像 https://mirrors.tuna.tsinghua.edu.cn/pytorch-wheels/ 只镜像了部分 CUDA 版本（cu118、cu121、cu124 等），没有 cu128 的 wheel。访问该目录直接返回 404。

修改措施

PyTorch wheel 必须从官方源下载，但其他普通 Python 包可以用清华镜像加速：

RUN --mount=type=cache,target=/root/.cache/pip \
    python -m pip install --upgrade pip -i https://pypi.tuna.tsinghua.edu.cn/simple \
 && python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128 --force-reinstall --timeout 300 --retries 5 \
 && SKIP_MOTION_CORRECTION_IN_SETUP=1 python -m pip install -r docker_requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple --timeout 120
  • pip 升级 → 清华镜像
  • torch/torchvision → PyTorch 官方源（唯一支持 cu128 的地方）
  • 其他依赖（gradio、transformers 等）→ 清华镜像
问题 #4

PyTorch 官方源下载卡死 — 大文件传输中断

现象

从 PyTorch 官方源下载 torch wheel（~2.3 GB）时，下载进度条停在一个位置不再更新。pip 进程仍在运行（CPU 4.3%），但：

  • 日志文件不再更新（最后修改时间停留在数分钟前）
  • 网络活动为零
  • 磁盘没有写入
  • 进程文件描述符无变化

等了 70+ 分钟仍然卡住，最终只能手动终止。

根本原因

PyTorch 官方 CDN（download.pytorch.org）从国内访问不稳定，大文件下载过程中连接可能静默断开。pip 默认的超时和重试策略不足以应对这种情况。

修改措施

给 pip 加上超时和重试参数：

python -m pip install torch torchvision \
  --index-url https://download.pytorch.org/whl/cu128 \
  --force-reinstall \
  --timeout 300 --retries 5
  • --timeout 300：单次操作超时 5 分钟（默认 15 秒太短）
  • --retries 5：失败后自动重试 5 次

如果还是卡住，备选方案：

  • 手动下载 wheel 文件到本地，COPY 进容器安装
  • 临时设置 TEXT_ENCODER_DEVICE=cpu 用 CPU 模式跑
问题 #5

py-soma-x 从 GitHub clone 超时 — 国内无法访问 GitHub

现象

PyTorch 和所有 CUDA 依赖都安装成功了，但在安装 docker_requirements.txt 时失败：

fatal: unable to access 'https://github.com/NVlabs/SOMA-X.git/':
Failed to connect to github.com port 443 after 129408 ms: Connection timed out

等了超过 2 分钟（129 秒）连 GitHub 都连不上。

根本原因

docker_requirements.txt 第 10 行指定了从 GitHub 仓库安装：

py-soma-x @ git+https://github.com/NVlabs/SOMA-X.git

这要求容器在构建时能访问 github.com:443。但国内网络环境访问 GitHub 不稳定，经常超时。而且 Docker 构建容器内的网络不走主机的代理配置。

修改措施

发现 py-soma-x 已经发布到 PyPI（版本 0.1.0，2026-03-16），功能完全一致：

# 改之前（需要从 GitHub clone）
py-soma-x @ git+https://github.com/NVlabs/SOMA-X.git

# 改之后（直接从 PyPI 下载，几秒完成）
py-soma-x==0.1.0

这个改动完全无副作用：PyPI 上的 wheel 和 GitHub 源码是同一个版本。

问题 #6

--no-cache 导致每次全量重新下载 ~4GB 依赖

现象

每次修改 Dockerfile 或 docker_requirements.txt 后重新构建，都要从头下载所有 PyTorch 和 CUDA 依赖包（约 4-5 GB），耗时 30-70 分钟。

根本原因

两层机制叠加导致了重复下载：

1. Docker 层缓存失效

Dockerfile 中 COPY docker_requirements.txt 在第 5 层，RUN pip install 在第 11 层。Docker 的层缓存规则是：一旦某层失效，后面所有层都失效。修改 docker_requirements.txt 会导致第 5 层失效，连带第 11 层也要重跑。

第 5 层: COPY docker_requirements.txt  ← 改了 py-soma-x 那行 → 失效
第 6 层: COPY setup.py
第 7 层: COPY pyproject.toml
...
第 11层: RUN pip install torch + requirements  ← 被迫重跑！

2. --force-reinstall 强制重新下载

即使 BuildKit cache mount（--mount=type=cache,target=/root/.cache/pip）保留了之前下载的 wheel 文件，--force-reinstall 参数会让 pip 忽略已安装的包，重新下载和安装。

3. --no-cache 雪上加霜

加上 docker compose build --no-cache 后，连 Docker 层缓存都跳过，所有 13 个步骤全部重做。

修改措施
  • 不要使用 --no-cache，让 Docker 自动缓存未变化的层
  • 确认 Dockerfile 稳定后不再改动
  • 如果一定要清除缓存，只清除需要重跑的那一层
最佳实践：把经常变化的文件（如 requirements.txt）的 COPY 放在不变的文件之后，减少缓存失效的范围。
问题 #7

GPU 0 被占满 — 容器默认使用 GPU 0 导致 OOM

现象

机器上有 8 张 RTX 5090，但 GPU 0 被其他任务占满（16969/32607 MiB，利用率 100%）。容器启动后如果 PyTorch 尝试使用 GPU 0，会与其他进程争夺显存。

根本原因

docker-compose.yaml 中设置了 NVIDIA_VISIBLE_DEVICES=all，容器内 PyTorch 默认选择 GPU 0（torch.cuda.current_device() == 0）。

修改措施

将 docker-compose.yaml 中的 GPU 可见性改为只使用空闲的 GPU 2：

# 改之前
- NVIDIA_VISIBLE_DEVICES=all

# 改之后
- NVIDIA_VISIBLE_DEVICES=2

如果想用多张空闲卡：

- NVIDIA_VISIBLE_DEVICES=2,7

先用 nvidia-smi 检查哪些卡是空闲的，再指定。

问题 #8

旧镜像未清理 — 容器使用了 cu130 而非 cu128

现象

明明 Dockerfile 已经改成了 cu128，构建也显示成功。但 docker compose up 启动后，容器里的 PyTorch 仍然是 2.12.0+cu130，而不是期望的 2.11.0+cu128：

docker exec text-encoder python -c "import torch; print(torch.__version__)"
2.12.0+cu130   # 期望: 2.11.0+cu128
根本原因

Docker 构建产生了新镜像，但旧的 cu130 镜像没有被删除。docker compose up 可能使用了旧的镜像缓存。text-encoder 和 demo 两个服务虽然共享同一个 image: kimodo:1.0 标签，但构建过程中它们的 layer digest 不同，导致混乱。

修改措施

彻底清理旧镜像和容器后重建：

docker compose down       # 停止并删除容器
docker rmi kimodo:1.0     # 删除旧镜像
docker compose build      # 重新构建（不加 --no-cache）
docker compose up

确认新镜像的 PyTorch 版本：

docker exec text-encoder python -c "import torch; print(torch.__version__)"
# 应该输出: 2.11.0+cu128

最终稳定的配置

Dockerfile 第 36-39 行（关键修改）：

RUN --mount=type=cache,target=/root/.cache/pip \
    python -m pip install --upgrade pip -i https://pypi.tuna.tsinghua.edu.cn/simple \
 && python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128 --force-reinstall --timeout 300 --retries 5 \
 && SKIP_MOTION_CORRECTION_IN_SETUP=1 python -m pip install -r docker_requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple --timeout 120

docker_requirements.txt 第 10 行（关键修改）：

# 改之前: py-soma-x @ git+https://github.com/NVlabs/SOMA-X.git
py-soma-x==0.1.0

docker-compose.yaml GPU 设置：

- NVIDIA_VISIBLE_DEVICES=2

RTX 5090 + PyTorch + CUDA 版本兼容性矩阵

PyTorch wheel CUDA Toolkit sm_120 支持 最低 Driver 版本 主机 12.9 驱动 结论
cu126 CUDA 12.6 不支持 12.6+ ✅ 不可用 不认 sm_120
cu128 CUDA 12.8 支持 12.8+ ✅ 可用 ✅
cu130 CUDA 13.0 支持 13.0+ ❌ 不可用 驱动太旧
cu132 CUDA 13.2 支持 13.2+ ❌ 不可用 驱动太旧

结论：对于 RTX 5090 + CUDA Driver 12.9 的组合，cu128 是唯一可用的版本。
