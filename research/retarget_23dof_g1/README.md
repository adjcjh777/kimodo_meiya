# G1 23DOF Retargeting Investigation

## Goal

Test whether motion generated by the Kimodo 34-joint G1 model can drive the 23DOF Unitree G1 skeleton.

## Current Context

- Existing experiment folder: `test_retarget_23dof/`
- Existing conversion script: `kimodo/scripts/retarget_g1_23dof.py`
- Source Kimodo G1 motion model: 34 joints / 29 MuJoCo hinge DOFs plus floating base.
- Target Unitree G1 variant: 23 hinge DOFs. The current URDF used by the visualizer is fixed-base because its floating joint is commented out.
- Test artifact: NPZ. CSV outputs are intentionally not part of this investigation.

## First Suspect

The first confirmed bug is in `test_retarget_23dof/visualize_mujoco_23dof.py`: the default target
`g1_23dof.urdf` has its floating base joint commented out, so MuJoCo loads a fixed-base model with
23 qpos values. The retargeted NPZ stores 30 values (`7 root + 23 joints`). The old visualizer
truncated the first 23 columns, which fed root xyz/quaternion values into leg joints. The visualizer
now strips the first 7 root columns when the model is fixed-base.

The next suspect is the qpos zero convention.

The current script converts Kimodo motion to the 36-column G1 MuJoCo qpos and then slices out six joints:

- waist roll
- waist pitch
- left wrist pitch
- left wrist yaw
- right wrist pitch
- right wrist yaw

This may be insufficient because the 36-column qpos is produced with `mujoco_rest_zero=False` by default. That means joint angles are not necessarily the same convention as a MuJoCo/URDF model that expects `q=0` to be the robot rest pose. Feeding those raw angles directly into a 23DOF model can produce large pose errors, especially around chained joints with body `quat` offsets.

## Test Path

1. Generate or reuse a Kimodo G1 34-joint NPZ.
2. Convert it with `python -m kimodo.scripts.retarget_g1_23dof input_34dof.npz -o output_23dof.npz`.
3. Run the headless checker:

   ```bash
   python research/retarget_23dof_g1/check_23dof_npz.py test_retarget_23dof/test_walk_23dof.npz
   ```

4. If the checker passes, inspect visually:

   ```bash
   python test_retarget_23dof/visualize_mujoco_23dof.py test_retarget_23dof/test_walk_23dof.npz
   ```

## Questions To Resolve In Order

1. Confirm whether the 23DOF URDF should stay fixed-base for this test or be converted to floating-base.
2. Confirm the target model's joint order and zero-pose convention.
3. Compare three outputs on the same generated clip if visual artifacts remain:
   - 34DOF qpos in the original Kimodo convention.
   - 34DOF qpos with MuJoCo rest-zero convention.
   - 23DOF qpos sliced from the correct convention.
4. Validate root frame conversion: Kimodo y-up/z-forward to MuJoCo z-up/x-forward.
5. Validate locked joints: dropping a joint is not equivalent to preserving its child transform unless the 23DOF model has already absorbed that fixed transform.

## Acceptance Criteria

- The same generated walking clip can be visualized in the 23DOF target model without inverted limbs, flying legs, or root/frame mismatch.
- Joint names and qpos columns are generated from the target model definition, not from hard-coded assumptions alone.
- A diagnostic script can print joint order, joint ranges, first-frame qpos, and geometry height ranges for the target model.
- The retargeted NPZ stores `qpos_23dof` as 30 columns (`7 root + 23 joints`); fixed-base tests consume columns `7:`.
