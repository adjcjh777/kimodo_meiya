G1 到 ELF3 重定向工作总结

日期：2026-05-29

1. 目标

当前目标是建立一条可重复的动作生成和重定向链路： Kimodo Docker CLI 生成宇树 G1 29DOF 动作， 然后将 G1 动作重定向到半醒/BXI ELF3，并批量录制 MuJoCo 视频用于检查。

2. 目录整理

顶层 test_retarget_23dof 已经整理进 research， 后续重定向相关实验都从 research 进入。

  • research/retarget_23dof_g1：保留 G1 23DOF 的早期验证、示例 NPZ、URDF 和诊断脚本。
  • research/retarget_g1_to_elf3：放置当前 G1 生成、G1 原始 MuJoCo 查看、G1 到 ELF3 重定向、ELF3 查看和视频录制工作流。

3. ELF3 资产

已将 ELF3 MJCF 和 STL mesh 资产放到： 

research/retarget_g1_to_elf3/assets/bxi_elf3

资产来源是 mjlab 的 bxi_elf3 目录。ELF3 模型和 Kimodo G1 一样都是 7 root + 29 hinge qpos，但不能直接播放，仍然需要按关节语义、root 高度和 joint limit 做重定向。

4. Prompt 批量生成

10 条动作 prompt 放在： 

research/retarget_g1_to_elf3/prompts_10_g1.json

批量生成脚本是： 

research/retarget_g1_to_elf3/generate_g1_prompt_batch.py

每条 prompt 默认生成 10 秒动作，Kimodo 模型按 30Hz 输出，即每条动作 300 帧。 输出会同时保留 G1 的 .npz 和 .csv。

5. G1 到 ELF3 重定向

第一版使用直接语义 qpos 映射，映射文件是： 

research/retarget_g1_to_elf3/joint_map_g1_to_elf3.json

重定向脚本是： 

research/retarget_g1_to_elf3/retarget_g1_to_elf3_baseline.py

输出 ELF3 .npz 中保存 qpos_elf3， 同时默认写出 36 列 MuJoCo qpos 顺序的 .csv，便于后续工具兼容。

6. 一键工作流

已封装总入口： 

research/retarget_g1_to_elf3/run_g1_to_elf3_workflow.sh

默认执行三步：

  1. 通过 Docker Kimodo CLI 生成 G1 动作。
  2. 将 G1 NPZ 批量重定向到 ELF3 NPZ 和 CSV。
  3. 批量渲染 ELF3 MP4，并打包 zip。
research/retarget_g1_to_elf3/run_g1_to_elf3_workflow.sh

7. 查看和录制

查看原始 G1 动作：

python research/retarget_g1_to_elf3/visualize_mujoco_g1.py \
  research/retarget_g1_to_elf3/generated_g1_10s/walk_forward.npz

查看重定向后的 ELF3 动作：

python research/retarget_g1_to_elf3/visualize_mujoco_elf3.py \
  research/retarget_g1_to_elf3/generated_elf3_10s/walk_forward.npz

批量录制：

python research/retarget_g1_to_elf3/render_elf3_videos.py
生成动作、ELF3 输出、MP4 和 zip 都属于本地可再生产物，已经通过 .gitignore 排除。 代码、prompt、映射、README 和 ELF3 资产保留在版本库中。
